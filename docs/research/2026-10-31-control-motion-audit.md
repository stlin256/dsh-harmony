# DSH Harmony 控件与界面动效审计

日期：2026-10-31

状态：调研与设计建议，尚未作为完成度声明。本文供后续动效 spec、实施表和真机 E2E 使用。

## 1. 目标与判断标准

DSH Harmony 的动效应服务于三件事：

1. **因果清楚**：操作后立即出现反馈，结果出现时能看见“从哪里来、到哪里去”。
2. **阅读稳定**：滚动、流式 token、增量加载和列表刷新不能打扰正在进行的阅读。
3. **触感高级**：用少量连续、克制的位移和透明度表达层级；不用统一加速、弹跳或大面积模糊制造“活泼”。

“流畅”不能简单解释为时长更短。感知流畅来自：

- 按下后 100ms 内出现可辨认反馈；
- 页面和覆盖层只在状态边界播放入场/退场；
- 手势期间元素跟手，松手后再用物理解算落位；
- 高频内容更新不触发装饰动画；
- 减少动态效果、低电量和大列表场景均有稳定降级；
- 同一动作只有一个主要动效所有者，避免父子容器重复滑动、缩放和淡入。

视觉方向延续 DSH 的紧凑、安静、信息优先与工具感。动效不使用夸张回弹、旋转、霓虹发光或无意义连续循环。

当前主要问题：

- 时长和曲线散落在 100、110、160、180、200、210ms 等不同位置，没有统一 token；
- 大量普通按钮没有应用层按压态，视觉响应依赖 ArkUI 默认效果，透明按钮和行点击尤其容易显得“没点到”；
- 页面进入和返回大多都用同一个 `x: 8` 方向，无法表达导航层级；
- 抽屉只播放条件插入过渡，Pan 手势本身没有跟手位移和速度投影；
- 工作区/会话的排序、置顶、跨区移动没有统一的空间连续性策略；
- 聊天没有显式“回到最底”控件；`followTail` 只在自动跟尾逻辑中使用；
- 流式回复、增量列表和缓存首绘需要严格避免入场动画，目前主要靠调用点自觉；
- `NativeImageView` 的 PinchGesture 每次 update 都调用 `animateTo`，连续手势可能排队并产生缩放迟滞；
- `NativeFileBrowser` 的目录进入以透明度/缩放代替横向层级连续性；
- Loading、错误、成功复制和空态多数组件直接替换内容，没有统一的短过渡或避免布局跳动策略。

## 3. 统一的动效语言

### 3.1 四条原则

**即时反馈，延后装饰。** 按压、开关和菜单触发在 80–120ms 内给出颜色或轻微 scale 变化。内容加载完成后的装饰只用于说明层级变化。

**连续性优先于速度。** 页面、抽屉、菜单和预览保持明确的出发/返回方向。返回动作不应重新从同一方向进入。

**滚动与流式内容不播放入场。** 每个 token、每个滚动进来的列表项、每次缓存刷新都必须直接呈现。只在结构性新增、置顶迁移、删除完成等语义边界播放短动画。

**直接操作使用物理，程序状态使用确定性曲线。** 拖拽、抽屉滑动、缩放等手势跟手；程序触发的页面、展开和状态切换使用有限时长的确定性曲线。全应用不统一使用弹簧。

### 3.2 建议 token

以下为首轮建议值，最终以真机观感和帧率调整。时长是感知预算，不是强迫动画等待。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `press` | 80–100ms | 按钮/行按压、图标明暗、检查态 |
| `micro` | 100–140ms | chevron 旋转、复制成功、短暂状态交换 |
| `compact` | 140–180ms | 消息披露、工具卡、Diff 展开 |
| `standard` | 180–220ms | 设置子页、文件层级、菜单进入 |
| `layer` | 220–260ms | 抽屉、全屏预览、共享元素退化为遮罩层 |
| `scrimIn` | 160–200ms | 抽屉/覆盖层背景遮罩进入 |
| `scrimOut` | 120–160ms | 遮罩退出，应快于主体退出 |
| `scrollSettle` | 220–320ms | 跟随进度衰减滚动到消息末尾 |

曲线建议：

- **Enter**：`ease-out`，动作先快后稳，常用 180–220ms；
- **Exit**：`ease-in`，让用户快速确认撤销，常用 120–180ms；
- **Direct manipulation settle**：低回弹、接近临界阻尼的 spring；
- **Scroll boundary**：只用系统 `EdgeEffect.Spring`，不对内容项本身施加弹簧；
- **Reduced motion**：所有非必要位移、缩放和共享元素立即切换，只保留不超过 80ms 的透明度状态反馈。

不得把动画时间用于人为延迟网络结果、许可写入、消息提交或页面可用性。

| --- | --- | --- | --- | --- |
| 普通图标/文字按钮 | 多数透明 Button 无显式按压态 | 底色提升一档 + `scale 0.985`，90ms；抬起 100ms 恢复 | 不做弹跳；忙碌时不用反复缩放 | 透明度/主题色即时或 80ms 过渡 |

| 思考过程披露 | 110–200ms 改变插入内容，chevron 同步旋转 | header 保持不动，body 高度/透明度展开 150ms；chevron 140ms | 不对整条消息重新入场；不扫描全文 | 直接展开/收起，block 直接出现 |

| 审批/问题卡 | 状态直接变化 | 首个可操作操作后 90ms 按压；提交中只锁本卡；成功淡出结果 180ms | 不让倒计时数字跳帧驱动整卡动画 | 状态直接替换 |

| 抽屉 | 条件插入 + `x: -28` | 手指挥动时面板跟手、遮罩随位移；松手按位移和速度判定，spring settle 220–280ms | 不先播放固定动画再跳一次；不延迟命中区 | 点击切换时 180ms ease-out slide |

| 错误/重试 | 直接插入文本 | 原位行 120ms fade；保持父容器尺寸稳定 | 不做 shake；不让错误推动整页大幅跳动 | 直接显示 |
| 连接状态横幅 | 直接插入 | 只在真实失败后出现，140ms fade + 4vp 下移；恢复 160ms 退出 | 加载和缓存同步时不得显示 | 直接显示/消失 |
| 图片手势缩放 | update 内逐帧 animateTo | 手势期间直接赋值跟随；松手/双击复位时 180ms settle | 连续手势不得排队；不做高回弹 | 手势直接跟手，复位即时/短 fade |

## 5. 页面与层级动效

导航的空间关系必须稳定：

```text
设置 root
  → child 从右进入
child
  → root 向右退出

聊天
  → 抽屉从左侧展开
抽屉关闭
  → 向左退出

聊天/列表
  → 预览层从内容表面上升
预览关闭
  → 反向下降
```

具体建议：

- 设置 root/child 使用单一 `pageEnter/pageExit`，不要对不同 tab 使用不同方向。
- 返回路径必须调用反向 transition，不能把新 root 再次从右侧推入。
- `SideBarContainer` 宽屏嵌入式布局切换不播放大位移；窄屏抽屉才使用横向过渡。
- Popup、Sheet 和 ContentCover 优先保留系统原生容器动效；内容只补充一层不超过 4vp 的位移或 0.98 scale，避免动效叠加。
- 在 API 26 支持共享元素且收益明确时，只用于图片缩略图→全屏预览等强对应场景。API 23 使用 fade + 小比例 scale 降级。

## 6. 列表、置顶与工作区顺序

目标数据语义：

- 置顶会话组成工作区列表之上的独立区，不重复出现在普通工作区内。
- 取消置顶后回到其真实工作区，按最后交互时间排序。
- 普通工作区内部默认按最后交互时间降序；同时更新的会话以 ID 作稳定排序。
- 工作区自身顺序可手动调整，并持久化到当前 Host/account；普通 metadata refresh 不得覆盖手动顺序。
- 置顶/取消置顶和工作区重排使用 Host 权威合同与乐观 UI；失败时回到原区/原顺序并原位提示。

动效表达：

- 置顶区 header 始终存在，即使为空也只在用户展开管理区域时显示轻量占位。
- pin 操作以“同一行身份”迁移：源行 90ms 淡出，目标区 180ms fade + 4–8vp 收拢。若距离跨屏，不制作穿过整个列表的轨迹。
- unpin 后回到工作区，目标位置由最后交互时间计算；源区和目标区彼此独立更新，不对整棵列表做 `onDataReloaded` 式抖动。
- “最后交互时间”应由权威会话字段派生，缓存首绘与网络刷新不得把 `cacheLoadedAt` 当作交互时间。
- 工作区拖动排序只在 header 上提供明确拖动热区；拖动期间 header 抬升，插入线出现，其他 header 以短线性位移让位。松手后 180ms 落位，不使用夸张弹簧。
- 切换搜索、折叠或筛选属于视图切换，旧行不应飞入新位置；直接替换或 100ms fade。

## 7. “回到最底”控件

建议加入一个原生浮动控件，而不是固定在输入框内部的永久按钮：

- 用户离开尾部超过约 80vp 或一整条消息时出现；
- 位置在 composer 上方、右侧安全区内，视觉直径 38–40vp，命中区至少 44vp；
- 图标使用向下箭头；箭头下方可加一个 4vp 蓝点表示有新输出，但不显示长文案；
- 出现：150ms fade + 6vp 上移，不缩放；
- 消失：120ms fade + 4vp 下移；
- 点击：先停止阅读锚定，再滚到末端；普通距离 220–260ms ease-out，长距离可用 280–360ms 低回弹或系统滚动；
- 流式更新期间按钮保持稳定，不随每个 token 重播；
- 减少动态效果时直接出现；点击后直接跳到末尾；
- 用户再次手动滚到接近尾部时自动隐藏；
- 输入框获得焦点、键盘弹起、内层工具内容滚动和抽屉打开时按钮不得误出现。

按钮不是新的阻塞层，也不代替“新消息已到达”提示。打开会话后只应在存在明确历史位置时显示。

## 8. 高频状态与性能边界

必须不播放逐项入场动画的状态：

- 流式 token/reasoning/tool argument 更新；
- 增量历史页 prepend；
- 缓存快照替换和后台 metadata refresh；
- 滚动进入视口的普通列表项；
- chunked markdown 解析和代码高亮结果；
- 窗口旋转/尺寸变化；
- 键盘 resize；
- 同一会话的 status heartbeat。

允许一次结构动画的状态：

- 新提交的本地用户消息首次落位，可 120–160ms fade + 4vp 上移；
- 完成后的最终 assistant 消息可在已有流式组件上完成一次 100–140ms 状态收束，但不能替换节点；
- 置顶/取消置顶、归档撤销、手动排序落位；
- 新目录数据替换旧目录时的内容交叉过渡；
- 连接横幅真实出现/消失。

执行规则：

- 手势 update 中只更新几何值，不启动大量 `animateTo`；
- `LazyForEach` 的结构变化优先使用稳定 key 和精确数据通知，避免整表 reload；
- 动画只作用于合成友好的透明度、位移、scale 和小面积背景色；不反复动画布局高度导致的超长内容重新测量；
- 对 1,000+ 行过程组、代码块和 Diff，只动画容器一次，不逐行 stagger；
- 低电量、系统减少动态效果或用户设置关闭时，全部降级为即时状态交换与不超过 80ms 的 opacity。

## 9. 等待、加载与反馈

- 按键/菜单/导航点击后必须立即有按压或选中反馈；网络进度不能成为唯一反馈。
- 首次空数据加载使用紧凑骨架或单行 spinner，稳定高度；已有缓存时只显示 1–2px 进度或局部更新点，不切换到整页 spinner。
- 加载更多只在触发点附近显示状态，完成内容直接追加并保持视觉锚点。
- 错误在原操作位置出现，避免全局 Toast 代替可恢复错误。
- 成功状态（复制、保存、排序）使用 800–1200ms 的简短图标/文字交换，不弹大对话框。
- 跨端保存或未知结果使用“待同步/未确认”稳定状态，不能先播放成功动画再撤回。

## 10. 可访问性与动效策略

- 所有可动画控件均有静态可辨识的 disabled/pending/error 状态。
- 动画不作为唯一的信息载体：展开方向同时改变文字/图标状态，错误同时有文本。
- 关键点击目标至少 44×44vp；视觉 glyp 可保持 28–36vp。
- 大字体环境下，避免把按钮文案固定在动画宽度中；先完成布局再淡入。
- `NativeExperience.reducedMotion()` 必须覆盖全部组件，而不仅是当前少数 transition。
- 建议把统一门控实现为共享 helper，例如 `NativeMotion.animate(context, token, action)`，内部统一处理 reduced motion、低电量和 token；生产代码不直接散落 duration 常量。

## 11. 建议实施优先级

| 优先级 | 范围 | 原因 |
| --- | --- | --- |
| P0 | 统一 motion token/helper；按钮按压；流式/滚动零入场门控 | 直接决定“高级感”和感知流畅 |
| P0 | 回到底部浮动按钮 + 跟尾状态机 | 长会话可用性 |
| P0 | 抽屉手势跟手与退出方向；连续 pinch 不排队 | 现有关键交互迟滞 |
| P1 | 设置 push/pop 方向、菜单与预览统一层动效 | 建立稳定空间模型 |
| P1 | 思考/工具/Diff 容器展开和 chevron 同步 | 高频阅读路径 |
| P1 | 置顶迁移、取消置顶回区和工作区拖排落位 | 用户当前明确需求 |

## 12. 真机 E2E 观感清单

- 60Hz/120Hz 设备上检查抽屉跟手、松手 settle 和背压；快速反向拖动无跳帧。
- 逐屏检查按钮按下到视觉反馈是否在主观 100ms 内；透明图标按钮不能像未响应。
- 在亮色、暗色、自动主题、减少动态效果、低电量和大字体下重复核心交互。
- 长列表快速拖动、展开 100+ 工具过程、加载历史页和流式期间观察阅读锚点是否跳动。
- 向上阅读时出现回到底部按钮；点击后落点准确；再次接近底部后按钮消失。
- 置顶/取消置顶：行迁移只发生一次，图标、分区、最后交互排序一致；失败可恢复。
- 工作区拖动排序：header 抬升、插入线、其他项让位、松手落位和重启持久化一致。
- 菜单/popup、模型气泡、设置子页、文件浏览器和图片预览返回时无残影、无双重动画。
- 连续捏合图片无 lag；手势结束只发生一次复位/落位动画。
