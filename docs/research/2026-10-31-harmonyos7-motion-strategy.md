# HarmonyOS 7 动效策略与工作区导航研究

状态：动效研究与实施基线  
日期：2026-10-31  
适用范围：DSH Harmony 原生界面、紧凑侧边抽屉、工作区与会话管理、聊天滚动、设置与预览表面  
兼容基线：`compatibleSdkVersion 6.1.0(23)`，`targetSdkVersion 26.0.0`

本文回答三类问题：

1. 当前 App 的控件和界面应形成怎样的统一高级感；
2. HarmonyOS 7 提供了哪些适合这些界面的原生动效能力，API 23–25 如何降级；
3. “回到底部”、置顶独立区、工作区反序排序和会话“最后交互时间”排序应采用怎样的交互与动效语义。

本文是研究与设计基线，不代表功能已经实现。实施范围和验收证据由 spec、自动化测试与 E2E 清单另行记录。

## 1. 结论摘要

本项目采用 **“Quiet Precision / 克制精确”** 作为视觉与动效风格：

- 视觉继续服从 DSH 的紧凑、冷静、功能优先语义：中性表面、细描边、黑白主文本、DeepSeek 蓝强调、小圆角层级和真实业务图标。
- 动效表达因果、层级与连续性，不承担装饰任务。禁止无状态变化的呼吸、漂浮、粒子、无意义旋转和持续玻璃反光。
- 高级感来自节奏、可中断性和空间连续性，不来自一律缩短时长。触控反馈要快，布局与表面切换要留有可感知的收束。
- 用户手势优先：拖动、抽屉、滚动由手指直接驱动；释放后从当前位移和速度继续收束，不能回到起点重播定时动画。
- 数据排序与视觉动画分离。用户改变筛选、分组或排序模式时直接替换最终布局；只有少量状态更新导致主动重排时才播放轻量重排动画。
- 系统或 App 开启“减少动态效果”时直接进入最终状态。弱化透明度、低算力设备或 API 23–25 上使用清晰不透明表面，不依赖 API 26 沉浸材质。

## 3. HarmonyOS 原生能力矩阵

| 能力 | API 与用途 | 本项目用法 | API 23 降级或风险 |
| --- | --- | --- | --- |
| `UIContext.animateTo()` | API 10；显式状态动画 | 页面、浮层和控件状态的标准入口 | 不使用已废弃的全局 `animateTo()` |
| `animateToImmediately()` | 依入口标为 API 12 或 23 | 仅在必须立即发布状态时使用，需能力保护 | 普通代码不依赖；减少动效优先直接赋值 |
| `keyframeAnimateTo()` | API 11；分阶段受控动画 | 少数需要严格阶段时钟的复合动效 | 普通控件不用关键帧，避免时钟碎片 |
| `Curve` | API 7；标准缓动枚举 | 提供 `FastOutSlowIn`、`LinearOutSlowIn`、`Friction` 等语义曲线 | 全版本可用 |
| `curves.responsiveSpringMotion()` | API 9；即时、可中断触控响应 | 按压、拖动释放、抽屉和可跟手切换 | 保留 SDK 建议的默认参数；减少动效时禁用 |
| `curves.springMotion()` | API 9；物理弹簧 | 列表落位、跨分区收束等少量空间变化 | 时长由物理参数和前一速度决定，不能套固定 duration |
| `curves.interpolatingSpring()` | API 10 | 需要明确 0→1 插值的特殊情况 | 普通 UI 优先 `springMotion` |
| `TransitionEffect` | API 10 | 浮层、菜单、页面与非共享元素的进出场 | 减少动效时使用 `IDENTITY` |
| `geometryTransition()` | API 11 | 同一逻辑对象在两个布局位置间连续移动 | 只有稳定同一节点时使用；不得伪造跨列表共享身份 |
| `PanGesture` offsets / velocity | 偏移 API 10/11，速度回调 API 10 | 抽屉、列表拖动和速度接续 | 手势中直接更新位移，不在每帧启动新动画 |
| `motionBlur()` | API 12 | 极少量高速运动的辅助效果 | 默认禁用；不作为常规“高级感”手段 |
| `ImmersiveMaterial` | API 26 | 系统级浮层/标题材质和交互形变 | API 23–25、材质关闭、减少透明或省电时回退清晰表面 |

`sharedTransition()` 虽在旧 API 可用，但 Exchange 模式只连续位置和尺寸，字体等内容属性可能在动画末尾突变。本项目不使用它承载聊天气泡、设置文字或动态列表；需要同源变化时优先验证 `geometryTransition()`，否则使用低位移淡入淡出。

## 4. 视觉风格：Quiet Precision

### 4.1 表面与层级

- 主页面使用中性的纯色或近纯色表面；浅色和深色主题均以明确对比为目标，不靠大面积透明玻璃。
- 侧边抽屉、菜单、动作表和预览使用高于内容的表面层级。只有 API 26 支持且系统策略允许时才使用沉浸材质。
- 分隔优先使用 0.5–1vp 描边和留白。阴影只在浮层需要脱离背景时使用，不在普通列表行反复堆叠。
- 圆角继承 DSH 的 4/8/12/16/20/28vp 层级：小控件 8–12vp，卡片/输入区 12–16vp，大表面 20–28vp。
- 状态色保持语义：DeepSeek 蓝用于主操作和选中，黄色仅用于等待，红色仅用于错误和危险动作。

### 4.2 密度、字体和控件

- 继续使用 DSH 的紧凑信息密度。会话行优先单行标题和少量状态图标，详细工作区归属通过辅助信息或无障碍标签提供。
- 视觉 glyph 可为 14–18vp，触控目标至少 44×44vp。返回、三点、齿轮等可点击控件不能只按可见图形大小设置热区。
- 主文本、次级文本和辅助文本层级清晰；不增加解释实现原理的大段说明。
- 选中、按压、焦点、禁用和忙碌必须有独立又稳定的状态，不通过持续闪动表示加载。
- 所有 SVG 使用当前主题语义色或明确的主题资源，不能写死只在深色主题可读的白色。

### 4.3 动效性格

- 短促反馈有“触感”，但不过度弹跳。
- 页面和浮层移动距离保持在 4–16vp 的小范围，除非它们本来就是从屏幕边缘进入的抽屉。
- 不使用连续装饰动画；同一时刻最多保留一个主要空间动效。
- 不在流式 token 更新时为整行、整段 Markdown 或整个列表添加入场位移。
- 动画结束应停在清晰、可点击的稳定状态，不允许菜单因弹簧尾摆长时间阻挡后续点击。

## 5. 动效 token

### 5.1 时间

| Token | 时长 | 用途 |
| --- | ---: | --- |
| `motion.press` | 80–100ms | 按钮、图标、卡片按压与松开 |
| `motion.micro` | 120–160ms | 选中背景、图标状态、展开箭头、轻提示 |
| `motion.overlay` | 160–220ms | 菜单、气泡、Sheet、动作浮层 |
| `motion.navigation` | 180–240ms | 设置二级页、原生 pane、返回 |
| `motion.surface` | 220–300ms | 完整抽屉、预览等大表面 |
| `motion.scrollReturn` | 220–320ms | 回到底部；距离越远取更长时间上限 |

“更快”不等于更流畅。触控反馈可以接近即时，菜单需要可识别的进出场，抽屉和回到底部需要让用户理解空间变化已经完成。

### 5.2 曲线

| 语义 | 曲线 | 说明 |
| --- | --- | --- |
| 标准状态 | `Curve.FastOutSlowIn` | 对应 DSH 的 `cubic-bezier(.4,0,.2,1)`，作为默认曲线 |
| 淡出/离开 | `Curve.FastOutLinearIn` 或较短的同源反向转场 | 离开通常比进入短 20–40%；不引入无关新方向 |
| 手势即时反馈 | `curves.responsiveSpringMotion()` 默认参数 | 用于按压、拖动中跟随和可中断状态 |
| 空间落位 | `curves.springMotion(response, damping, overlap)` | 建议以 `0.30–0.36s` response、`0.88–0.92` damping 起步，真机再调 |
| 远距离滚动 | 标准曲线 + 距离上限 | 不做会回弹过冲的长距离 spring |

用户第一次拖动某一对象后，释放动画必须使用当前手指位移和 `velocityX/velocityY` 接续。手势被再次触碰时立即接管，不能排队等待上一段动画完成。

## 6. 控件与界面映射

| 场景 | 动效 | 必须避免 |
| --- | --- | --- |
| 按钮/图标按压 | 90ms 内 opacity 或 scale 至约 0.97–0.99，热区不缩放 | 阴影膨胀、长按弹跳、整行位移 |
| 开关与复选状态 | 120–160ms 轨道/图标颜色和位置过渡 | 只改轨道、文字/图标颜色仍停留在旧主题 |
| 菜单/模型气泡 | 160–200ms 淡入 + 0.98→1 scale，从锚点方向出现 | 打开整页、空白首帧、从屏幕中心飞出 |
| 设置二级页 | 200–240ms 淡入 + 8–12vp 轻位移，返回反向 | 横向 tab 整体滑动或将二级页做成孤立页面 |
| 侧边抽屉 | 手势直接跟手；释放后用响应弹簧；遮罩同步透明度 | 每次 pointer update 重启 duration 动画 |
| 工作区折叠 | 箭头 120ms，分组内容 160–200ms；保持锚点 | 折叠时整页跳动、重复滚动补偿 |
| 过程/思考展开 | 沿用既有 70ms fade、50ms delay、110ms height 的协调时钟 | 再叠加通用 200ms 位移造成二次运动 |
| 会话置顶/取消置顶 | 菜单先收起；行在原位确认后淡出/轻移位，目标区插入并高亮一次 | 让列表所有会话横跨整个屏幕“搬家” |
| 会话/工作区重排 | 长按后 lift，插入线 2vp；释放后 180–220ms 落位 | 拖拽中触发布局写入或网络写请求 |
| 图片/文件预览 | 220–260ms 淡入 + 最大约 4% scale；返回反向 | 从状态栏下方溢出、长时间过冲 |
| 回到底部 | 220–320ms 平滑滚动 + 按钮 120ms 收起 | 瞬移、长弹簧回弹、流式输出抢滚动 |

### 6.1 当前实现的差距

当前 `NativeWorkspace.ets` 已有 `animatePane()`、抽屉平移、菜单/预览 `TransitionEffect` 和跟尾滚动，但存在以下需要收口的模式：

- 多处局部动画使用固定 `200ms + Curve.EaseInOut`，没有区分按压、浮层、导航和大表面。
- 页面入场普遍使用 `0.992` scale；缩放应当只出现在有明确锚点的表面，普通 pane 更适合小位移和透明度。
- 用户向上滚离底部时，目前只更新 `followTail`，没有可见的回到底部入口。
- 工作区列表当前把 pinned 会话排在各 workspace 内，不满足“全局置顶独立区”。
- 当前会话拖动只支持 `workspace/insertSessionBefore`，工作区自身排序尚无 UI 调用 `workspace/insertBefore`。
- `nativeWorkspaceSessions()` 的默认排序使用 `updatedAt`；“最后交互时间”的稳定定义还需要在 spec 中固化为单一数据源。

## 7. 回到底部按钮

### 7.1 状态

按钮只在以下条件成立时出现：

1. 用户主动向上滚动，或当前尾部距离视口底部超过阈值；
2. 用户已经离开跟尾位置，输出不会自动抢回阅读位置；
3. 输入区可用且按钮不会遮挡消息或系统手势区。

建议使用带滞回的状态：

- 距底部超过 `max(160vp, 0.35 × 视口高度)` 时显示；
- 距底部回到 `48vp` 以内，或 `followTail` 恢复时隐藏；
- 快速向上滑动可在距离略小时提前显示，避免按钮出现得过晚；
- 从后台恢复、切换会话和减少动效切换时重新计算一次，不能用旧会话的显示状态。

### 7.2 视觉与位置

- 采用悬浮圆形或胶囊按钮，视觉尺寸约 36–40vp，触控热区至少 44vp。
- 默认显示 DSH 向下箭头；存在尚未读到的尾部更新时可用小圆点或紧凑数字，不增加长句。
- 位于输入区上方、屏幕右侧安全区内，水平与输入卡片边距对齐；底部间距避开 `safeArea.bottom` 和软键盘。
- 使用系统/当前主题表面、轻描边和必要阴影。API 26 材质不是基础依赖。
- 出现和消失只做 120ms opacity + 4vp 轻位移；消息滚动本身使用 `motion.scrollReturn`。

### 7.3 行为

- 点击前先把 `followTail` 恢复为 true，再滚动到真实尾部；不能只滚一个视口。
- 距离较短时直接平滑 `scrollEdge(Edge.Bottom)`；距离较长也只在 220–320ms 内完成一次有方向的滚动，必要时使用列表定位 API 到达可靠尾部，不使用会越过内容的夸张 spring。
- 点击后立即开始按钮收起，滚动完成前禁止重复触发。
- 如果流式输出仍在继续，滚动完成后才恢复自动跟尾；若用户在动画中再次拖动，立即中止自动滚动并继续保持 `followTail=false`。
- 减少动态效果时直接切换最终位置；按钮状态仍更新。

## 8. 置顶区、工作区和排序

### 8.1 信息架构

抽屉中的顺序固定为：

1. App 名称与搜索；
2. 新会话、插件、自动化任务、更多；
3. 独立的“置顶”区；
4. “工作区”区；
5. 固定在底部的设置入口。

“置顶”与“工作区”是两个语义分区。置顶会话位于所有 workspace header 之上，而不是在各自 workspace 内重复一次。

- 置顶行保留原 workspace 归属；取消置顶后回到原 workspace。
- 搜索时仍可展示匹配结果，但结果分组不得改变真实归属或 pin 状态。
- 收起“置顶”只影响显示，不修改 Host pin 集合。
- 空置顶区默认不占据可见空间；有会话时才显示标题和计数。

### 8.2 置顶/取消置顶动效

1. 会话三点菜单关闭。
2. 菜单动作发起后，原行进入 120–160ms pressed/selected 状态。
3. Host `pinSession`/`unpinSession` 采用乐观更新，但同一会话只允许一个 in-flight 动作。
4. 更新后，如果同一行节点能稳定保留，使用低幅度淡出/淡入和小位移；不使用跨全屏的搜索式飞行动画。
5. 目标分区标题和计数同步短淡入，目标行仅高亮一次。
6. Host 拒绝或超时则回滚分区，短暂显示短错误状态，不重复动作。

置顶与普通会话不能跨区拖动。分区变化只能通过菜单动作发生，避免拖拽中隐含 pin 写入。

### 8.3 会话排序

普通工作区内部按“最后交互时间”倒序，规则应在 spec 中固化为：

- 优先使用 Host 对会话的权威 `updatedAt`；
- 选择会话本身不应篡改持久 `updatedAt`；
- 同一 Host 响应中出现时间相同时，用 session ID 做稳定决胜；
- blank 的当前工作会话可以保留在所属工作区前部，但不得进入全局置顶区；
- 本地“最近打开”只能作为导航恢复信息，不能冒充最后交互时间，除非 spec 明确扩展 ranking policy。

如果产品要表达“用户刚点开也算最近交互”，应新增独立的本地 `lastOpenedAt` 并在 spec 中说明它与 `updatedAt` 的合并、跨设备差异和退出清理规则；未定义前不直接混用。

数据变化造成的 1–2 行重排可以有 180–220ms 落位动画。切换搜索、分组、排序模式或进入另一个工作区时立即发布最终顺序，不播放大规模搬家动画。

### 8.4 工作区排序

- 每个 workspace header 提供明确可发现但紧凑的拖动入口；长按 header 也可启动拖动。
- 工作区顺序是独立于会话 membership 的用户定义顺序。
- 拖动中只更新本地预览；释放后先乐观更新，再调用 Host `workspace/insertBefore({ workspaceId, beforeWorkspaceId? })`。
- 其他 header 使用 `springMotion` 让位；被拖项以轻微 lift、描边或系统拖拽预览表示层级。
- 请求失败恢复 Host 最近一次好顺序，并显示短状态。不能把 membership 数组重排当作工作区排序成功。
- 重排不能改变会话所属工作区、置顶状态或 workspace 路径。
- 只有工作区或搜索/筛选规则真实变化时才更新布局；把行移出和落位拆成同一事务，避免中间重复行闪烁。

## 9. 聊天与滚动

- 只在新消息、提交成功回显或用户要求时产生滚动行为。流式 token 更新只更新文本，不逐 token 触发位移动画。
- 跟尾时尾部稳定；用户离开尾部后暂停抢位置。回到底部按钮是恢复跟尾的唯一轻量显式入口。
- 加载早期历史使用视觉锚点补偿。旧内容保留时不用全列表透明度闪光掩盖跳动。
- 发送回显只入场一次，正式消息替换 pending 行时保持行身份，不重复弹跳。
- Markdown 表格、代码块、文件链接、图片更新不得导致整个消息卡进入场重播。
- 拖动滚动的预加载属于性能策略，不能用“加载指示动画”替代；缓存命中时优先保留旧内容并增量替换。

## 10. 设置、菜单和预览

- 设置根页和二级页属于同一导航栈。进入二级页时页面轻推入，返回按相反方向退出；系统返回使用同一状态机。
- 横向分类 tab 不用于手机设置。分类行保持纵向、紧凑和可滚动。
- 菜单、模型选择、更多操作均从锚点出现，使用同一套 160–220ms 浮层 token。缓存内容先出现，再更新数据，禁止先显示空白帧再弹入。
- Sheet/预览先完成安全区和状态栏布局，再播放透明度和轻 scale；禁止内容从状态栏下方进入后自行下移。
- 任何菜单在退出动画期间不能继续接收新动作；弹簧过冲不应延长可交互延迟。

## 11. 架构与实现约束

实施阶段应新增统一的 motion token/helper，例如 `NativeMotion.ets`，组件只使用语义 token，不散落魔法数字：

- `press()`、`micro()`、`overlay()`、`navigation()`、`surface()`；
- `gestureSpring()`、`layoutSpring()`；
- `respectReducedMotion()` 返回时长/曲线或直接执行终态；
- `transitionOverlay()` 等组合工厂；
- 公共 helper 只返回参数，不直接操作某个具体组件的滚动或路由状态。

实现原则：

1. 先更新数据和导航状态，再选择动画；动画不能成为成功条件的来源。
2. 只在 transform、opacity 和必要颜色属性上做高频动画。避免每帧改变文本尺寸、边框宽度和外层布局。
3. `LazyForEach` 使用稳定 key；重排必须通过精确 move/change 发布，不能整表 reload。
4. 执行滚动/拖动动画前检查目标节点仍属于当前 generation、会话和主题。
5. 页面不可见、应用后台、减少动效或低算力策略启用时取消非必要动画。
6. API 26 能力由版本、设备支持和系统策略三重保护；API 23 使用完全不透明的普通表面。
7. 不把材质、玻璃反光或 motion blur 当作默认视觉质感。
8. 视觉状态必须支持浅色、深色、大字体、软键盘、横屏、分屏和 320vp 级窄屏。

建议数据边界：

- `PinnedSection`：全局 pinned membership 的只读投影；
- `WorkspaceSections`：Host workspace 顺序与每个 workspace 的普通会话；
- `SessionRanking`：`updatedAt DESC + id` 的纯函数；
- `WorkspaceOrdering`：乐观顺序、请求 generation 和可回滚 last-good；
- `ScrollTailState`：`followTail`、离尾距离、按钮可见性和滚动 generation。

## 12. 性能与感知流畅

- 动画目标是稳定 60Hz；支持 120Hz 的设备不应因逐帧布局而掉帧。
- 动画期间避免重新计算完整 transcript、反复 filter/sort 或全量 `onDataReloaded`。
- 工作区重排只更新 header 顺序；会话状态更新只移动受影响行。
- 抽屉打开时保留聊天内容和输入组件，不在手势每帧重建主页。
- 滚动预加载、缓存首绘和旧内容保留优先于加长 skeleton 动画。
- 复杂 blur、shadow、motionBlur 和材质不能用于每个列表行。必要时只应用在顶层表面，并提供低算力回退。
- 连续动画结束要清理计时器、订阅和临时 generation，防止后台耗电。

## 13. 无障碍与系统偏好

- 系统减少动效或 App“减少动态效果”任一开启：所有非必要位移、缩放、弹簧、转场结束动画取消，直接进入最终状态。
- 减少透明：材质替换为清晰表面，仍保留层级描边和必要的短淡入。
- 省电模式或后台：停止滚动装饰、材质交互形变和持续重排等待；状态文字保留。
- 触控目标至少 44×44vp，回到底部、拖动 handle、三点和菜单动作必须有可读无障碍名称。
- 置顶区的无障碍语义要包含“置顶”和原工作区名称；工作区重排要宣布新位置。
- 动画不能成为唯一的状态表达；选中、运行中、待确认、失败和连接状态始终有图标或文字。

## 14. 风险与待验证项

| 风险 | 处理 |
| --- | --- |
| 弹簧 duration 与常规 `AnimateParam.duration` 语义不同 | helper 明确区分时间动画和物理动画，不共用一个 duration token |
| `LazyForEach` 重排可能重播相邻行 | 稳定 key + 精确 move；真机检查整表闪烁 |
| 跨置顶区和 workspace 的动态节点难以共享 | 默认低幅度淡出/淡入；只有验证稳定同源节点后才启用 geometry transition |
| 工作区写请求乱序导致旧顺序覆盖新顺序 | request generation、last-good 和失败回滚 |
| API 26 材质与 API 23–25 外观差异 | 以清晰表面为基线，材质只做增强 |
| 流式输出期间自动滚动抢夺阅读 | `followTail` 与滚动 generation 分离；回到底部显式恢复 |
| “最后交互时间”跨设备语义不稳定 | spec 固化 `updatedAt` 为权威；若加入本地打开时间，单独建模并说明 |
| 真机 120Hz 与低端机手感不同 | 参数集中为 token，按帧率和设备等级仅调整表现，不改变行为 |

## 15. 建议 E2E 清单

本节供后续 spec 合并成正式 E2E 表。[ ] 表示待实施或待真机验证。

- [ ] 浅色/深色下逐一检查按钮、抽屉、菜单、设置、聊天、文件预览和回到底部按钮的可读性。
- [ ] 系统减少动效与 App 减少动效分别开启，再同时开启；所有转场直达终态，功能仍可用。
- [ ] 抽屉从边缘拖动后中途反向、快速甩出和慢速释放；始终跟手，遮罩与位移同步。
- [ ] 菜单在锚点上方、下方、靠边和软键盘上方打开；不越安全区、不空白首帧、不长时间锁定。
- [ ] 聊天处在底部时，新输出保持跟尾；向上滚离后输出不抢位置，按钮按阈值出现。
- [ ] 回到底部按钮点击后到达真实尾部，流式输出继续时恢复跟尾；动画中再次拖动可立即取消。
- [ ] 置顶会话只出现在全局置顶区；取消置顶返回原 workspace，不落入“其他会话”。
- [ ] 置顶、取消置顶和 Host 失败回滚各验证一次；期间无重复 RPC、无列表行身份重播。
- [ ] 普通会话按最后交互时间倒序，相同时间稳定；选择会话本身不改变持久排序。
- [ ] 工作区拖动排序成功、失败回滚、快速连续两次排序和断线重连后对账；会话 membership 不变。
- [ ] 用户切换搜索/分组/排序模式时无大范围搬家动画；增量状态导致的单项重排有轻量落位。
- [ ] 流式更新、代码高亮、表格、图片和工具过程高频更新时不整页闪烁，拖动滚动保持流畅。
- [ ] 退回后台再恢复、旋转、分屏和窗口尺寸改变后，动画目标不会落到旧节点或旧会话。
- [ ] 320vp 窄屏、大字体、横屏和折叠屏展开后，回到底部按钮、置顶标题与拖动 handle 不溢出。
- [ ] 支持 API 26 材质和不支持的设备分别检查；材质关闭或低电量时保留完整层级与操作。
- [ ] 低端真机后台滚动/拖动无持续 CPU 动画；动画结束后计时器、订阅和临时 generation 已清理。

## 16. 推荐实施顺序

1. 建立 `NativeMotion` 语义 token 和 reduce-motion helper，替换新增代码中的散落时长。
2. 实现回到底部按钮及跟尾状态机，先完成滚动正确性，再调视觉参数。
3. 重构会话投影为“置顶区 + 工作区”，固化最后交互时间排序和取消置顶归属。
4. 增加工作区拖动排序、乐观更新、Host `workspace/insertBefore` 与失败回滚。
5. 对抽屉、菜单、二级页、置顶迁移和重排逐项收敛动效。
6. 本地静态/单元检查后统一做真机 E2E，不以浏览器或 mock 代替 ArkUI 手势与帧率验证。
