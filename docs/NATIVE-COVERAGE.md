## 收敛标准

1. 为每个模块列出实际可见控件、触发入口、数据接口、状态转换、取消／重试和错误行为。
2. 使用相同服务端状态验证原版与原生的正常及异常操作，核对消息、附件、投影和交互决策。
3. 对原生组件做大字体、读屏、软键盘、横竖屏、分屏、减少动效和长数据验收。
4. 仅对经确认无法原生实现的内容或第三方页面采用兼容承接，并记录原因；其余待办不能借兼容面板标为完成。

当前自动化通过的是网关及服务模型测试。没有可用的 HarmonyOS SDK／设备，尚未验证 ArkTS 编译和实际原生组件行为；因此不发布 100% 完成或性能达标声明。
