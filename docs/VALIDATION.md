## 接手验收顺序

1. 先按 DEPLOYMENT.md 编译原生工程。记录 DevEco/SDK/设备 OS 版本、签名 profile 是否包含 FIDO2 权限及 Push 能力，修复并回传具体编译诊断。
2. 在系统浏览器打开 HTTPS 网关，首次密钥注册 Passkey，再退出后登录。确认无效密钥、错误域名不能注册/登录；手机时钟、域名及 TLS 证书正确。
3. 在 APP 重复测试 Passkey 弹窗、取消验证、成功登录、重启保留登录；测试网关设为 Passkey 时，APP 选无验证仍不能绕过。无验证部署需单独启用服务端开关。
4. 在原版 Harness 中创建会话，发送任务，检查实时流、工具、历史和文件上传。测试 native 返回、刷新、断网提示、无效证书拒绝、站外跳转拦截及系统安全区域。
5. 在 APP 开启通知；确保注册成功，再通过实际任务触发完成、失败和审批事件。分别测试前台、后台、锁屏、终止 APP 进程；核实 Huawei 返回和系统展示，勿把“接受消息”当作“设备收到”。
6. 点击通知：冷启动和热启动均进入通知页，显示正确的会话标识。**当前不直接跳转 Harness 的特定 SPA 会话路由**，由用户从会话列表进入，避免绑定未经验证的路由结构。
7. 关闭通知或退出，再触发事件，确认原设备不再注册及不继续投递。断网退出应显示错误，不应伪报成功；恢复网络后重试。token 更新后手动重新开启。
8. 重启网关，确认已接受且未过期的队列续发。停掉网关后产生任务，再恢复，确认插件在一小时内重试；如果同时重启 Harness，尚未交接到网关的插件内存通知可能丢失。

## 当前边界

- 只支持单用户工作空间；无验证模式本身没有身份隔离。
- Passkey 依赖系统 ArkWeb 和签名权限；一个 owner credential，丢失时采用管理端重置流程。
- Push token 暂无自动轮换监听，APP 需手动重新注册；一小时 TTL、八次投递尝试，不能保证必达。
- 插件只通知完成、失败和审批，不通知普通提问；停止插件时清理内存队列。
- 网关进程应只有一个实例拥有同一个 SQLite 文件；不支持多实例并发消费和跨服务器队列。
- API 保留前缀 `/pocket/`，Harness 如新增同名路由需要调整集成。
- 修改连接前需要成功退出撤销旧设备；当前没有“离线强制换服”按钮。
