# DSH Harmony 视觉与动效设计

日期：2026-10-31

状态：实施基线。需求见
[动效、置顶分区、工作区排序与回到底部需求](../requirements/2026-10-31-motion-workspace-pin-scroll-bottom.md)。

## 设计语言

DSH Harmony 使用 **Quiet Precision / 克制精确**：

- 视觉延续 DSH 的紧凑、安静、信息优先和工具语义。
- 表面使用中性色、细描边和小圆角，不堆叠装饰阴影或大面积玻璃效果。
- DeepSeek 蓝只用于主操作、焦点和选择；黄色表示等待，红色表示错误或危险。
- 动效表达因果、层级和连续性。没有状态变化的漂浮、呼吸、粒子、闪光、无意义旋转和
  长时间回弹都不属于产品语言。
- “流畅”以感知稳定为准。触控反馈要快，浮层和导航要保留可识别的收束；高频内容更新
  不应制造等待感或持续运动。

## 表面层级

| 层级 | 示例 | 形状与材质 |
| --- | --- | --- |
| Base | 聊天、设置根页 | 不透明主题背景，0.5–1vp 分隔 |
| Raised | 输入卡、会话行、过程组 | 8–16vp 圆角，轻描边或一档表面色 |
| Overlay | 菜单、模型气泡、动作菜单 | 16vp 圆角，锚定出现，必要时轻阴影 |
| Surface | 手机抽屉、全屏预览 | 20–28vp 视觉关系，安全区先布局后动画 |
| Chrome | 顶栏操作、API 26 标题材质 | 只增强控件，不承载正文层级 |

紧凑布局的视觉 glyph 可为 14–18vp，可点击热区至少 44×44vp。字号和行高随系统字体
缩放，图标与触控区不随文字一起被挤压。

## 动效语义

| Token | 时长 | 曲线 | 用途 |
| --- | ---: | --- | --- |
| `press` | 90ms | FastOutSlowIn | 按钮、图标、行的按下和松开 |
| `micro` | 140ms | FastOutSlowIn | 选中、箭头、复制成功、短状态交换 |
| `overlay` | 190ms | FastOutSlowIn | 菜单、模型气泡、动作浮层 |
| `navigation` | 220ms | FastOutSlowIn | 设置二级页、文件层级、pane 返回 |
| `surface` | 260ms | FastOutSlowIn / responsive spring | 抽屉、全屏预览等大表面 |
| `scrollReturn` | 240–320ms | 方向明确的缓动 | 回到底部 |

退出动作通常比进入动作短 20–40%。直接操作使用
`curves.responsiveSpringMotion()`；跨分区的少量落位可使用低回弹
`curves.springMotion(0.3–0.36, 0.88–0.92, 0.25)`。弹簧的物理时长不套用普通
`duration`。

## 页面方向

```text
设置 root -> child: child 从右轻移 8–12vp 并淡入
child -> root: 反向退出

聊天 -> 抽屉: 遮罩先出现，抽屉跟手或从左进入
抽屉 -> 聊天: 遮罩先退，抽屉向左或随手指离开

聊天 -> 预览: 预览从内容表面上升并淡入
预览 -> 聊天: 按进入方向退出
```

系统 Back、页面返回按钮和 App 导航状态必须走同一路径。开启减少动效时，所有页面直接
切换到最终状态。

`TransitionEffect` 必须通过 `.animation(NativeMotion.implicit(token))` 绑定语义
时长；不能只依赖外层偶然的 `animateTo`。页面根层级与二级层级使用相反方向的 X
位移，以表达进入和返回。

## 控件规则

| 控件 | 动效 |
| --- | --- |
| 图标/文字按钮 | 90ms 按压色或 0.985–0.99 缩放，热区不缩放 |
| 三点菜单 | 保持触发点高亮，菜单 140–190ms 从锚点淡入 |
| 模型气泡 | 缓存先出现，局部刷新；不显示空白 loading 帧 |
| 思考/工具/Diff 展开 | 箭头与内容在同一时钟收束，长内容只动画容器一次 |
| 开关/选择 | 只锁本行；成功短交叉反馈，失败恢复权威值 |
| 抽屉 | 手势时只更新位移和遮罩透明度，松手后从当前位置收束 |
| 文件/图片预览 | 240ms 内淡入和不超过 4% 的 scale，安全区先稳定 |
| 连接状态 | 仅在真实失败后出现；使用短句“连接中断，正在尝试重连” |

## 列表与结构变化

- 首次加载、缓存替换、搜索、筛选、折叠和账号切换直接发布最终布局，不播放全列表搬家。
- 置顶/取消置顶使用局部离场和目标区入场；不绘制跨越整个列表的飞行轨迹。
- 工作区拖动时只有 header 抬升，插入线标明目标；其他 header 用短位移让位。
- 会话按最后交互时间排序。单个新交互导致的重排可播放一次轻量落位；流式 token 不按帧
  触发排序动画。
- `LazyForEach` 使用稳定 key，精确发布变更，避免整表 `reload`。

## 回到底部

- 使用聊天列表外层的 `Stack` 浮动控件，不插入消息列表。
- 视觉尺寸 40vp，触控热区至少 44vp；位于输入区上方、右侧安全区内。
- 用户离开真实尾部后延迟约 100ms 出现；到达尾部后立即隐藏。
- 有新输出时显示 6vp 蓝点，不显示持续动画。
- 点击后立即退出按钮状态、恢复 `followTail`，用 240–320ms 有方向地回到底部。
- 减少动态效果时直接跳到尾部。

## 性能与无障碍

- 高频动画只改变 transform、opacity、小面积颜色和必要阴影。
- 不在手势 update 中调用大量 `animateTo`，不在每个列表行使用材质或 blur。
- 捏合缩放期间直接更新 scale；只允许双击复位等离散动作使用语义动画。
- 动画不是唯一状态表达；展开、选中、错误、运行中和待确认始终有文本或图标。
- 按钮、拖动手柄和菜单项提供可读无障碍名称。
- 低电量、后台、减少透明度和减少动效必须退化到稳定、清晰、可操作的终态。

## HarmonyOS 能力边界

- API 9+ 可使用标准曲线和 spring；API 10+ 使用 `TransitionEffect`。
- API 26 的 `ImmersiveMaterial`、交互光效和系统材质只用于受支持的 Chrome 表面。
- API 23–25 使用完全不透明的主题表面；功能与信息层级不得依赖材质。
- 默认不使用 `motionBlur`、共享元素或几何过渡承载动态文字和长列表。只有稳定节点和
  明确收益时才启用，并提供淡入淡出回退。
