# DSH Harmony 原生交互规格

状态：研究与实施基线。本文定义目标行为；验收记录与模块覆盖表单独记录实际完成情况，不能由本文推导已全部实现。

## 1. 源码基线与目标

- 官方仓库：[deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)。
- 锁定 revision：`f3803c96974ad4a94195fb97e5c637e9c2a3afe3`，`0.2.2-alpha.2`；2026-10-29 核对官方 HEAD 与此一致。
- 研究分为聊天、工作区、设置与视觉三条，并补充非ui包贡献的入口及完整内置交互目录。证据见[聊天](research/upstream-chat.md)、[工作区](research/upstream-workspaces.md)、[设置与视觉](research/upstream-settings-visual.md)、[扩展交互目录](research/upstream-extended-ui.md)。源码引用均针对上述revision。
- 用 ArkTS/ArkUI 重写官方的状态、操作、排序、内容投影与错误恢复；保留原版图标和视觉语义。适配手机的改变限于可用空间、触控、键盘、安全区和系统返回。
- 不用原始 JSON 列表、临时网页或占位按钮冒充原生等价实现。第三方自定义页面与尚未移植的内置功能分别记录。不得把“打开兼容模式”记为完成该原生功能。
- 上游全部内置模块的范围见 [覆盖核对表](NATIVE-COVERAGE.md)。这里的优先级表示执行顺序，不将后面的模块从目标中删除。

## 2. 全局原则

| ID | 必须保持的行为 | 手机映射与验收 |
| --- | --- | --- |
| G01 | 一个服务端会话、一个权威日志/投影；UI 不修改模型可见内容 | 原生与兼容共用认证和会话。切换后不重复提交、不争抢同一审批 |
| G02 | 业务状态与导航/展开/草稿状态分离 | 设置及菜单覆盖时会话常驻。返回保留草稿、附件、历史窗口和阅读位置 |
| G03 | 同一记录生命周期内身份稳定 | 以 seq、callId、attemptId、rpcId 等官方身份对账；不得依赖显示文本去重 |
| G04 | 已知状态才显示成功、耗时和结果 | 未确认的提交不自动重发。错误、取消与中断不能伪装为成功 |
| G05 | 真实输入、回复、过程和系统上下文各有语义 | 隐藏系统注入，保留真实输入；通知唤醒、问题回答不能一并误删 |
| G06 | 文案短，详情按需查看 | 短状态、紧凑行、可展开正文；不在页面加入实现原理或大段教程 |
| G07 | 图标与主题采用官方原始素材及中性语义色 | 图标本地打包、保留许可；不能用字符/emoji 临时替代业务图标 |
| G08 | 操作可取消、异步可恢复，禁用态与忙碌态明确 | 点击一次产生一次操作；返回不会隐式取消已经受理的远端任务 |
| G09 | 地址与凭据来自配置 | 仓库、测试夹具、日志、截图、提交中无私人部署地址、凭据或签名文件 |

## 3. 信息架构与入口

### NAV：页面与返回

- `NAV01` 手机主路径为工作区/会话列表 → 会话 → 当前视图。宽屏可并列侧栏与会话。没有永久额外的 App 顶栏。
- `NAV02` 设置入口：原生侧栏的扁平齿轮；兼容模式向已信任 DSH 网页侧栏注入同一个齿轮，调用同一个原生设置页。
- `NAV03` 系统返回与页面返回使用同一导航状态：最上层预览/菜单 → 该功能二级页 → 功能根页 → 会话 → 列表。设置二级页只返回设置，不退出整个设置。
- `NAV04` 导航派生值必须统一计算，窗口尺寸改变不能覆盖当前弹层/子页的返回能力。组件销毁才取消所属订阅。
- `NAV05` 顶栏会话标题保留父/子会话层级。三种三点入口不得混淆：标题区utilities菜单为复制Markdown、下载日志、可用时反馈；tab栏三点为更多视图；侧栏会话三点为会话管理。注册来源还包含`session-query/session-log-export`，不能只扫描`ui-*`。
- `NAV06` 会话操作顺序：置顶/取消置顶 → 重命名 → 创建分支 → 归档/恢复 → 复制会话 ID。归档会话不提供置顶；模型、队列不塞入此菜单。
- `NAV06a` 标题区utilities复制完整服务端Markdown，不仅复制已加载窗口；日志经Host授权export route生成ZIP，可选择是否包含后代，手机使用系统保存选择器。忙碌时禁用对应操作，复制/下载失败分别反馈。
- `NAV07` 更多视图按官方视图注册顺序、固定偏好和可用宽度决定可见标签，聊天固定；默认溢出菜单列出其余视图与当前勾选，以及可用的插件浏览/创建入口。owner虽提供固定回调，官方默认菜单不消费它，不添加臆测的固定按钮。只有一个视图时隐藏视图栏；没有原生实现的视图记录为待移植，不伪造菜单项。

### WS：工作区与会话

- `WS01` 以 `workspace/follow` 的 baseline 与后续更新为权威，分别维护 `items`、`archivedSessionIds` 和 `pinnedSessionIds`。
- `WS02` 列表使用服务端 `blank` 隐藏空会话；当前正在编辑的空会话可保留在工作区新建位置。运行中或缓存中确有内容的会话不能被默认标题误删。
- `WS03` 默认按 updatedAt 降序、同值用 ID 稳定排序，当前 blank 最前，再将非归档 pinned 排前；手动顺序按 account 隔离保存在客户端，不能拿 membership 数组冒充用户手动偏好。搜索匹配 title、workspace label/cwd basename、完整 ID，250ms 防抖远端内容搜索，取消旧请求并按 ID 合并，不改写源数组。
- `WS04` 新建会话在选定工作区中创建。复用符合 preset 条件的已有空会话；`workspaceId` 与 `cwd` 互斥。指定 ID 的创建在超时后可通过列表核对。
- `WS05` 添加、重命名、排序、移除工作区与会话置顶、归档、恢复分别使用公开Workspace Controller合同。普通归档直接执行并可撤销；活动会话先请求，只有Host返回`workspace/session-active`后才询问停止活动并使用`stopActivity:true`，取消不停止。分支RPC只传`sessionId/atSeq?/allowMigration:false`；客户端increaseTitle策略在创建成功后单独rename，已有编号递增；rename失败不重做fork，不在后台强制迁移。
- `WS06` 目录选择的是远端文件系统，显示 Host 根、目录加载/失败/返回/确认；不可将手机目录当成远端目录。直接输入路径只是后备入口。
- `WS07` 会话选择保留各自草稿、附件、已加载窗口、过程展开和视图选择；切换后只显示所选会话的实时交互。

## 4. 聊天与执行过程

### CHAT：记录投影

- `CHAT00` 传输与权威窗口保留原始 `source`、完整调用参数、结果 `meta/content` 有序块、`error.code/details`、seq覆盖、Assistant revision及Inbox claim关系。Chat隐藏规则只作用于可见投影；不能先flatten或从journal丢弃字段，导致Trajectory与严格工具model不可还原。
- `CHAT01` 从官方 durable event schema 读取 `data.source`。`kind:user` 为真人；普通 context、system、记账事件不进入 Chat，但其 seq、替换与分页边界仍处理。旧日志仅对确定的注入前缀降级过滤，不按任意关键词删消息。
- `CHAT01a` context中工具增删通知依照上游 visibility 的例外显示；不能把全部非user来源一刀切删除。通知唤醒严格由claim判断，普通非人工输入不能升级为通知。
- `CHAT02` Inbox 领取批次决定普通 User、steering 与通知唤醒的区别。首个过程证据前的开场输入在过程控件上方；之后的可见输入留在原位并阻止整轮折叠。
- `CHAT03` `schedule`、`tool-jobs`、插件更新、目标/agent/团队/子任务/webhook 的有效轮次触发通知独立显示、默认收起；它们不是普通系统上下文，也不代表执行成功。
- `CHAT04` Assistant 内容按原始块顺序呈现。只有非空白推理生成推理行；工具协议块不显示为 Assistant 占位正文。图片与回复同样构成回复边界。
- `CHAT05` 同一 turn 相邻过程组成一个组；Step 或工具类别改变不拆组。回复、steering、轮次独立节点等真实边界拆组。隐藏节点既不入组也不拆组。
- `CHAT06` 工具以 `callId` 配对 preparing/start/result，以 `parentCallId`/`subCallId`/`rootCallId` 还原 PTC。准备态不可展开，参数结束不代表已执行。生命周期变化不替换调用身份。
- `CHAT07` 已完成轮次按官方资格折叠过程：失败、停止、过程后交错输入不整轮折叠；正常结束即使没有最终答案也可折叠。起点未加载时不得编造耗时。
- `CHAT08` 整轮 → 组 → 原子调用/推理三层显隐依次作用。整轮收起重置内部 disclosure；改变展示模式保留手动选择和行身份。
- `CHAT09` 已结算问答用一次用户样式气泡呈现，并与工具记录按调用身份去重；不因过程折叠而隐藏。迟到回答按官方交错输入规则处理。

### PREF：官方聊天偏好

这些是 Host profile 偏好，不用同名本地偏好冒充同步。

| ID | Host key | 行为 |
| --- | --- | --- |
| PREF01 | `ui-chat.transcriptView` | compact / standard / detailed / verbose。legacy normal、expanded 映射 detailed；Web 默认 detailed，Desktop 默认 standard；本手机原生默认 detailed，与非Desktop Web一致 |
| PREF02 | `ui-chat.collapseTiming` | completion 默认；next-input 保留最新真人交互段的运行呈现，下一次普通输入提交时协调收起；运行时placement=queued的输入/单独steer不触发，空闲时deliveryMode=queue的普通提交仍触发 |
| PREF03 | `ui-chat.foldedReplies` | all 默认；final 时阶段回复随过程折叠，最终回答保留；verbose 隐藏此设置 |
| PREF04 | 官方主题/字号/语言/链接偏好 | 使用上游字段与允许值；读不到时只使用明确默认，读取默认不写入远端 |

- 四档共享同一分组。compact 只摘要；standard 摘要带实时详情；detailed 运行轮次直接显示过程行、历史保留组头；verbose 全部平铺，仍需手动打开单个完整正文。
- 已结束组摘要取计数前三类别，稳定并列顺序；不显示次数。运行组取最近启动且仍运行的调用，不能用最近输出时间取代启动时间；后遍历同时间子调用优先。
- 标题实时切换最短 150ms，结束摘要立即切换。类别、详情字段优先级、准备态文案逐项对照上游，不修改 wire 工具名作启发式匹配。
- 分组模式的手动展开组限高为 `min(400vp, 50%可用视口)`、4vp 行距、8vp 头体间距；detailed运行平铺、verbose及延后收起期间平铺不设置组级限高。组内与外层跟尾独立。打开运行组从底部跟尾，历史组从顶部阅读。

### TOOL：原子工具视图

工具渲染分为不含系统 API 的纯 card model 与 ArkUI 视图；根调用和 PTC 子调用使用同一分派。非法或含糊输入保留原文的通用视图，不捏造结构。

| ID | 类别 | 必须实现的内容 |
| --- | --- | --- |
| TOOL01 | 通用 | 正常业务图标、标题、摘要、失败/中断、完整输入/输出与 Inspect（具备原生检查视图时才提供） |
| TOOL02 | read / read_image | 记录的路径、行号/范围、完整文本、图片元信息、授权预览、图片加载失败与重试；不自动重执行历史read工具 |
| TOOL03 | write / edit / str_replace_editor | 路径、按官方定义的输入大小、变更统计、紧凑diff与完整内容；失败/停止省略成功统计。apply_patch属于edit分类，但官方原子视图仍generic；若额外实现专用diff须标为移动扩展 |
| TOOL04 | grep / glob | 合法参数、描述优先、文件/行/片段，否定/含糊过滤器使用通用视图 |
| TOOL05 | bash / pwsh / terminal_send | 命令、记录 cwd、输出、退出码/信号；后台启动回执不等于进程完成；spill/persistent/error按官方 fallback |
| TOOL06 | web_search / web_fetch | 真实 HTTP(S) 链接、查询、来源和正文；系统打开外链，不产生伪来源 |
| TOOL07 | todo / goal / jobs / subagents | 从记录结果构建状态、层级、标题和操作回执；不是读取当前状态替换历史 |
| TOOL08 | ask_user_question / plan-review | 可回答时重新打开，同一批已回答记录只读回看；计划全文与批准/要求修改分离 |
| TOOL09 | AUTO_REVIEW_DENIED | 优先于专用工具视图，显示未执行裁决和归一化理由；持久错误保留原文 |

### INPUT：输入与提交

- `INPUT01` 输入区保留官方语义草稿：文本、引用、命令、文件/目录/会话 reference 和有序附件。普通换行与提交、IME 组合输入、可编辑/忙碌态分离。
- `INPUT02` 模型/推理选择属于输入区；显示当前 Host 选择，catalog 懒加载，模型与 reasoning 分栏/子页，返回仅退一级。
- `INPUT03` Idle 普通提交与 running 时 queue/steer 的路径不同。Queue 不是自动重复发送。运行且无可发送草稿时显示 Stop，停止请求不代表任务已经结束。
- `INPUT03a` `ui-conversation.busyEnter` Host偏好为queue（默认）/steer；主发送与Enter一致，Ctrl/Cmd+Enter选相反模式。手机显式发送优先，IME候选确认不触发提交。
- `INPUT04` 本地提交立即创建有 rpcId 的 pending echo，以日志/Inbox 结果对账后移交正式记录。网络结果不明确时保留草稿和状态，不创建新 ID 自动重发。
- `INPUT05` Queue以持久item ID编辑、移除、立即steer；只有全部content均为text的记录允许编辑，混合附件记录禁用编辑，不能转成纯文本覆盖。排队消息在输入区队列Dock管理，不藏进会话菜单。
- `INPUT06` 选择的图片和文件进入同一条有序横向附件栏；图片64vp，文件240×64vp，手机可横滑。上传、进度、失败重试、Host拒绝与移除各有状态。
- `INPUT07` 消息单图最长边240vp、保持比例；多附件64vp方图与文件卡同排、保留顺序。预览打开原图，系统返回/关闭归还焦点。
- `INPUT08` Slash commands、引用和计划/权限等入口按官方注册的能力和顺序显示。不得暴露服务器未提供的空入口。

### READ：滚动与生命周期

- `READ01` 新输出仅在跟尾时滚到底。向上阅读暂停跟尾；显式“回到底部”恢复。内层工具/过程滚动不得抢夺外层阅读。
- `READ02` 加载更早记录以第一个可见的正文语义项为锚点；整轮控件不作为锚点。按投影后的身份和偏移补偿，不能用原始事件数量推算列表下标。
- `READ03` 跨页替换/压缩不能复活已移除内容；旧历史保留到权威 replacement 替换为止。稳定 disclosure 跨补页与同 ID 更新保留。
- `READ04` 运行指示位于本轮尾部，普通pending transcript echo在它之前、当前轮待领取steering在它之后。显示已知开始时间推导的秒钟；缺起点只显示状态。断线冻结，重连恢复，不从本地打开会话时间编造耗时。running先false但turn/end未到时保留隐藏尾槽，避免尾部缩跳；减少动效时鲸鱼静态。
- `READ05` 断线横幅固定短句“连接中断，正在尝试重连”。快照完成才恢复可发送；保留缓存正文，自动恢复订阅，不自动重发用户消息。
- `READ06` 每次连接有 generation；旧连接迟到事件失效。重试遵循上游退避/抖动与握手时限，离线暂停、上线重试，认证失效进入登录且保留退出能力。

## 5. 审批与提问

- `ASK01` 只有存活且归属当前会话的请求启用决策按钮。历史记录和只读回看不能重新授权。
- `ASK02` 多题使用官方逐题翻页；推荐项预选只是草稿。单选自定义与选项互斥，多选可并存；跳过发空 selected，提交定位缺失项。题目/说明按实际溢出展开。
- `ASK03` timed 请求先 attachWait；首帧建立 deadline。焦点暂停、未修改时失焦恢复余量；首次编辑/“慢慢回答”改为无限。隐藏面板不等于委托或拒绝。
- `ASK04` timeout 放行后仍可回答，经 Host projection 的 continued 状态切换 answer Remote；同一草稿延续。发送 waterfall 结果不伪报已接受，等待权威投影结算。
- `ASK05` 答案按 session/callId/batch 隔离，切换、重连保留；投影关闭才清理。别的客户端先回答后，本地恢复到真实状态。
- `ASK06` plan-review 为紧凑“计划待审”，全文查看独立；同意使用指定批准标签，要求修改走既有取消等待语义并回到编辑器，不提交批准。

## 6. 设置、视觉与鸿蒙适配

- `SET01` 官方 Host 设置按部署注册分类和 access 决定是否显示；窄屏全屏、横向分类导航、内容16vp边距。不能把全部部署硬编码为同一插件目录。
- `SET02` App 扩展设置包括连接/认证、渲染模式、鸿蒙通知分级、后台策略、系统主题/动效/透明、卡片和关于；与 Host profile 设置区分归属。
- `SET02a` Host 设置使用 `settings/describe {}` 与 `settings/mutate {ns,ops,expectedRevision}`，mutate 参数不能包 request；同 namespace 串行写入，携带最新 revision，失败重新 describe 恢复权威值，断线/文档更新刷新。优先移植 ui-chat、ui-theme、locale；没有写权限禁用写操作并保留可读内容。
- `SET03` 关于使用打包 Logo，项目名、版本、版权/许可、打包作者 GitHub 头像/用户名、仓库和 Issues 链接。无全屏开关。
- `SET04` 连接默认原生访问密钥，Pocket ID Passkey 放下面；前者只需 DSH 插件，HTTP局域网与HTTPS公网均按服务端规则工作，Passkey HTTPS走认证页面。失败/取消时仍能返回、修改地址、退出。
- `VIS01` 官方菜单为锚定浮层，不是整页杂项表。宽144–360vp，4vp内边距、16vp圆角、13fp文字、14vp图标、组间0.5vp分隔；适配手机触控区时优先44vp行高，视口边距12vp，超长内部滚动。
- `VIS02` 中性背景、描边、正文与次级文本语义、DeepSeek强调蓝；错误红/等待黄只表达相应状态。按钮正常/按压/禁用/忙碌/焦点都定义。
- `VIS03` 动效100/200/300ms及官方缓动映射ArkUI；导航、菜单、过程展开、切换、发送回显连续，不给每次stream刷新加位移动画。遵从系统/本地减少动效。
- `VIS03a` 过程折叠使用官方专用时序：淡出70ms、关闭延迟50ms+高度110ms，与锚点补偿同一时钟完成，不统一套200ms或再追加一次滚动。
- `VIS04` 状态栏可见，内容处于顶部安全区；底部手势区与页面同色，输入区位于键盘与底部安全区上方，不加固定空白。布局随旋转、分屏、字体尺寸更新。
- `VIS05` 手机上 hover 操作有可触达替代，图标有无障碍名称，触控目标与文字尺寸可独立，后台时不持续运行装饰动画。

## 7. 其他内置模块的原生目标

以下仍在同一范围内，须从所属模块源码逐项拆出规范后实现，不用通用 JSON 页面替代：

| 交互族 | 对应模块 | 验收要点 |
| --- | --- | --- |
| 视图与检查 | trajectory、renderer、message-feedback、deliverables | 原始记录与Chat投影分开；token/时序/工具检查依据真实字段；反馈身份与文件打开 |
| 文档与远端文件 | sidebar-files、documentpreview、directory-picker、open-in-app | 目录分页/导航、授权读取、预览、变更、焦点与返回，远端与本地路径严格区分 |
| 运行控制 | plan、goal、jobs、schedule、subagent、workflow-run | 每种状态、取消、确认、重试、历史与实时数据分离，不把回执当结果 |
| 输入扩展 | commands、reference、input-trigger、permission-presets、skill | 注册能力、过滤与选择、语义草稿、权限/计划模式切换和失效状态 |
| Host配置 | settings-*、agent-preset、plugin-manager、plugin-market | 部署可用项、scope与access、变更验证、忙碌/失败/重启、敏感值处理 |
| 布局基础 | layout、dockkit、sidebar、sidebar-right/browser/terminal | 手机panel导航替代桌面并列，但保留所属会话、状态、关闭与恢复行为 |

## 8. 实施顺序与完成门槛

1. **P0 导航和可用性**：设置打开/返回/顶部对齐；统一导航状态；三点入口分离和锚定菜单；连接恢复与缓存；真机回归。
2. **P1 工作区**：权威快照、空会话、选择/新建/复用、归档/恢复/置顶、排序与目录选择；协议夹具与实际服务核对。
3. **P2 聊天**：事件投影与身份、系统过滤/唤醒/问答、四档偏好/整轮与过程、流式参数与工具模型、回显对账、锚点及跟尾。
4. **P3 输入和实时决策**：模型、队列Dock、有序附件、reference/commands、审批/问答/计划审核及故障恢复。
5. **P4 其他内置页面**：按第7节逐族实现；每族有单独源码依据、状态表、协议测试和设备验收。
6. **P5 发布**：检查脱敏、许可、README多语言、构建/签名/安装、远端插件部署与回滚记录、tag并推送；遵用户要求不查询Actions。

每条规格使用“待实施 → 自动化通过 → 真机通过”的证据记录，不笼统标记整个模块完成。测试优先验证与官方等价的状态/边界，视觉验收使用真实ArkUI布局与截图；浏览器或Kit mock不替代设备验收。

## 9. 最低验收场景

- 空会话、只有系统上下文的会话隐藏；未命名但有真人内容/正在运行的会话可见。
- 设置从两种模式打开；关于/连接返回一级；菜单点击外部、系统返回、旋转后均不穿透或退出错误层级。
- 单工具、并行工具、PTC、失败、中断、stream preparing、同step多回复、跨step同过程、interleaved steer、无最终答案、分页缺起点均与官方一致。
- 四档展示×两种收起时机×两种回复策略，切换不重建身份；短内容顶对齐，长内容无横向溢出。
- 滚离底部后输出不抢位置；加载旧页、过程折叠、压缩/替换后阅读锚点稳定；软键盘不遮输入。
- 正常发送、4xx拒绝、超时、服务重启、断网、迟到事件分别有明确状态，无消息重复提交。
- 多题、推荐预选、单选自定义、多选+补充、跳过、超时续答、他端先回答、计划要求修改与批准各走正确通道。
- 本地凭据/私人地址/真机对话截图不进入仓库；Push与普通后台模式行为继续按既有通知规格验收。
