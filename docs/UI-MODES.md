# 兼容模式与原生模式

DSH Harmony 提供两套界面，连接同一工作空间并共用登录态。兼容模式使用 ArkWeb 呈现 Harness 原版界面；原生模式使用 ArkUI 实现会话、原生交互和应用设置。首次使用默认兼容模式，顶部模式按钮与设置均可切换并保存选择。

**原生模式仍处于实验阶段，尚未达到全部内置 UI、组件行为和高级功能的 100% 覆盖。** 原生控件和内嵌兼容页面是不同实现，不能混计为原生覆盖。详见 [源码模块核对表](NATIVE-COVERAGE.md)。

## 当前能力

| 功能 | 原生实现 |
| --- | --- |
| 会话 | 无人为条数截断的懒加载列表、新建、指定目录与 Agent Preset、重命名、创建分支 |
| 对话 | 文本发送、图片发送、下一轮排队／下一步干预、停止执行、实时文本与思考过程 |
| 历史 | 向上自动分页、回放去重、消息替换、保留重连前已加载历史；不设置历史总条数上限 |
| 工具 | 原生调用／结果卡片与展开详情；专用工具的结构化交互尚未全部实现 |
| 模型 | 原生提供商／模型目录、推理强度选择；目录失败独立呈现 |
| 队列 | 待发送内容、编辑、移除、立即干预 |
| 审批 | 真实实时请求的允许一次／拒绝／委托其他客户端；历史审计记录不能再次审批 |
| 提问 | 单选、多选、自定义回答、审批与计划文本、限时请求、开始作答暂停倒计时、超时后的继续回答 |
| 图片 | PNG、JPEG、GIF、WebP 选择与发送；历史图片按需读取、原生预览与缩放 |
| 长内容 | 完整正文与思考内容；超长块使用原生虚拟列表阅读器和复制全文 |
| 应用设置 | 系统／浅色／深色主题、减少透明与动效、通知、卡片隐私及退出登录 |
| 待完成的内置页与第三方页 | 在内嵌完整工作空间中访问；不会永久改变已选的原生模式 |

Passkey 注册与登录临时使用共用的 ArkWeb 认证页。原生图片选择使用系统文件选择器；非图片附件上传仍由完整工作空间承接。计划审核的文字和选项已能原生处理，专门的差异比较、计划编辑和其他复杂控件不视为已完成。

## 连续使用与内容完整性

“打开完整交互”或“完整工作空间”会打开临时面板，原生工作空间保留在下面。关闭后返回已有会话、草稿及已加载记录。面板打开期间暂停原生实时连接，释放其交互应答代际，避免两套界面争抢同一审批；返回后重新获取实时状态。

安装可选的 [`@dsh-harmony/navigation`](../plugins/harmony-navigation/) Harness 客户端插件后，临时面板会通过公开的 `uiWorkspace.openSession` 服务打开原生界面当前会话。插件只消费 `dshHarmonySession` 查询参数，不访问 DOM 或私有状态。未安装时可以打开完整工作空间，但需要手动选择会话，不保证自动定位。安装方式见 [部署指南](DEPLOYMENT.md#原生界面的会话交接插件)。

永久切换两种 UI 模式仍会重建渲染界面。兼容页面的未发送草稿由 Harness 自身管理；切换前应保存。原生文本／图片草稿仅保存在进程内存，退出连接后清除。

应用与网关不再对正文、思考过程、会话总数、历史总条数或发送文本设置人为长度截断。分页的 60 条和初始窗口的 80 条只是每次读取的预算，能继续向前加载。分页使用原始事件的最早序号和固定历史切点，审计事件页不会导致游标停滞；已经被较新替换事件移除的内容也不会在读取旧页时复活。

超长块的主会话视图显示预览，点击“阅读全文”进入原生 `List / LazyForEach` 阅读器。阅读器按 4096 UTF-16 单元建立显示窗口，保持 Unicode 代理对完整；这是渲染分页，全文仍保留并可复制，没有固定末页。主会话列表和会话目录同样采用懒加载。HTTP 使用 Network Kit 流式接收，实时下行使用 WebSocket 分片，不再因超过旧的 2MB／8MB 阈值而丢掉内容。

目前已加载数据仍保留在内存，并非磁盘分页引擎；超大数据的内存、响应速度及持续滚动仍需真机验证。不把取消应用截断等同于无限物理内存，也不承诺绕过 Harness 服务端、模型或系统自身的格式和容量约束。

## 数据通路

原生模式不依赖隐藏 Web 页面读取聊天。Native Network Kit 使用自身网关的 HttpOnly `pocket` cookie，禁止重定向。上游 Harness cookie 只由网关持有，不进入客户端或桌面卡片。

网关原生协议版本为 **2**，需要同步更新网关和应用。固定的原生 HTTP 入口转接公开 Session API，包含列表、新建、分页、发送、停止、重命名、分支、模型、队列、图片和投影读取。`operation` 接口有显式操作白名单，不是任意 RPC 转发器。

`/pocket/native/live` 连接正式 Remote mux 的 follow、observeState、observeProjections 和 `$events`。原生客户端下行连接不接受命令；决定通过独立 HTTP 入口提交。交互映射绑定网关登录归属、连接代际和真实 eventId，主机撤销、退出或断开后不可重用。限时问题先建立 `userQuestions/attachWait`，超时发送协议规定的 `ASK_TIMED_OUT`，继续回答使用 `userQuestions/answer`。

所有变更操作均不自动重试。未确认的发送保留草稿，由用户核对后决定是否再次发送；未确认的审批暂停提交，等待重新同步。进入后台会停止原生实时连接及概览轮询。

## 外观与验收

布局延续 Harness 中性色、字体层级和控件圆角。窄屏在目录／对话间切换，宽屏并排显示；原生过渡遵循减少动态效果设置，系统材质仍受系统版本、透明偏好与省电状态控制。字体使用可缩放单位，键盘采用内容缩放避让。

自动化检查覆盖 HTTP／WebSocket 协议夹具、Kit 模拟下的状态和传输逻辑、Unicode 长内容、历史替换与重连、审批归属与撤销、限时提问、图片消息和会话交接插件。**这些不是 ArkTS 编译、完整 Harness 联调或真机性能测试。**

设备验收需覆盖完整会话、长历史滚动、阅读器、图片内存释放、队列竞态、多个设备同时审批、限时问题切后台、兼容面板的打开／关闭、插件自动定位、大字体、分屏／折叠屏与减少动效。内置功能的逐控件验收在覆盖表中继续跟踪。
