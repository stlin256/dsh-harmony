# DSH Harmony 历史连续预取与缓存可靠性需求

日期：2026-10-31

状态：已确认，进入实现。

## 真机反馈

网络短暂变差时，会话历史页加载一次失败后停止。用户必须重新滑动顶部才能再次
触发页请求。大会话在冷启动时也可能反复从网络加载。

## 功能要求

- `HISTORY-01` 会话进入 live 状态后主动、持续预取更早页面，直到服务端明确返回
  `hasMore=false`、历史游标不再前进或当前会话不再有效。
- `HISTORY-02` 单页请求失败不得结束预取。自动使用
  `600/1200/2400/4800/8000ms` 退避重试，之后每 8 秒继续尝试。
- `HISTORY-03` 网络和实时连接恢复后立即重新尝试，不等待下一次用户滚动。
- `HISTORY-04` 用户切到顶部、点击“更早”或接近顶部时，请求优先级高于低优先级
  后台预取。
- `HISTORY-05` 自动重试失败不反复弹出错误；401 继续走统一重新登录流程。
- `HISTORY-06` 切换会话、离开原生会话、退出登录或历史耗尽后，旧会话的计时器、
  页响应和重试不得写入新会话。
- `HISTORY-07` 用户正在阅读旧内容时，预取继续加载，但列表保持当前可见锚点；
  不因持续补页把视口拉回底部。
- `HISTORY-08` 服务端返回重复游标且没有新增行时视为无效页，不进入无限快速循环，
  改为退避重试。

## 缓存要求

- `CACHE-HISTORY-01` 加密 RDB 不再把整段会话 JSON 写入单个大文本字段。会话载荷
  按不超过 256 KiB 的字符串块保存并带 manifest。
- `CACHE-HISTORY-02` 读取任一块短暂失败时保留现有缓存，不立即删除；后续打开可
  再次尝试。
- `CACHE-HISTORY-03` 旧版单行缓存仍可读取；成功读取后下次保存迁移到分块格式。
- `CACHE-HISTORY-04` 缓存继续按登录范围隔离、加密、遵守 512 MiB 配额，并在退出
  登录时清理。

## 聊天消息操作

- `MESSAGE-ACTION-01` 用户消息的复制操作不额外占一行。普通点击继续用于查看
  链接等正文交互，长按消息复制完整文本；复制后只使用现有短反馈，不改变气泡
  高度。
- `MESSAGE-ACTION-02` 最终助手答复的“已完成”和复制继续位于同一行；运行中消息
  不显示额外复制行。
- `IMAGE-ACTION-01` 用户自己发送的气泡图片打开后使用与工作区图片预览一致的灯箱
  标题栏结构，并提供显式下载按钮；长按保存继续保留。

## 验证

- 单元测试覆盖退避序列、成功清零、重复游标和持续耗尽边界。
- 自动化源码契约覆盖会话切换、页面离开和 live 恢复时的预取取消/重启。
- 真机覆盖弱网断流、连续失败、恢复、快速切换会话、大历史冷启动和用户停留旧页
  时的锚点稳定性。
