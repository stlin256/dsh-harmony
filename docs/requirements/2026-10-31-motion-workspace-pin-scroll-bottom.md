# DSH Harmony 动效、置顶分区、工作区排序与回到底部需求

日期：2026-10-31

状态：已确认的实现范围。本文件记录用户要求；实现证据和真机验收状态分别见对应
spec、自动化测试与 E2E 清单。

## 目标

在不改变 DSH Host 权威数据语义的前提下，让原生手机界面具备一致、克制、可中断的
高级动效，并解决长会话、跨工作区置顶和工作区排序中的导航问题。

## 功能要求

### MOTION

- `MOTION01` 动效必须服务于反馈、层级和空间连续性，不使用无状态变化的装饰动画。
- `MOTION02` 按压反馈、状态切换、浮层、导航和大表面使用不同的语义时长与曲线。
- `MOTION03` 抽屉、拖动和直接操作在手指移动时跟手；松手后从当前状态收束，不重播。
- `MOTION04` 流式 token、增量历史、缓存刷新、主题重绘和普通滚动项不播放逐项入场。
- `MOTION05` 系统或 App 的“减少动态效果”开启时，非必要动画直接进入最终状态。
- `MOTION06` API 23–25 不依赖 API 26 材质、模糊或新动画对象；API 26 增强必须是可关闭的
  增量能力。

### SCROLL

- `SCROLL01` 用户离开真实列表尾部后暂停自动跟尾，新输出不得抢走阅读位置。
- `SCROLL02` 聊天区提供紧凑的“回到底部”浮动按钮，带安全区避让和至少 44vp 触控区。
- `SCROLL03` 按钮在离底后延迟出现，回到接近尾部时隐藏，避免在边界附近闪烁。
- `SCROLL04` 点击按钮恢复跟尾并到达真实尾部；减少动态效果时直接到最终位置。
- `SCROLL05` 离开尾部后新增内容可在按钮上显示紧凑圆点，不使用持续脉冲或长文案。

### WORKSPACE

- `WS01` 所有置顶会话位于工作区分组之上的独立“置顶”区。
- `WS02` 置顶行显示所属工作区标签；同一会话不得同时出现在工作区和置顶区。
- `WS03` 取消置顶后，会话回到 Host membership 指定的原工作区。
- `WS04` 工作区普通会话按最后交互时间倒序；Host `updatedAt` 是权威值，用户成功打开
  会话或发送消息可更新按账号隔离的本地排序提示。时间相同时以 session ID 稳定决胜。
- `WS05` 普通工作区的会话顺序不再由会话拖拽覆盖。
- `WS06` 工作区本身可拖动排序；拖动只调用 Host `workspace/insertBefore`，不改变
  membership、路径、置顶或归档状态。
- `WS07` 工作区排序先乐观更新；Host 拒绝、超时或断线时恢复最近一次成功顺序并提示。
- `WS08` “置顶”“其他会话”和底部设置入口不参与工作区拖动。

## 视觉与交互要求

- 继续使用 DSH 的紧凑密度、中性表面、细描边、真实业务图标和 DeepSeek 蓝强调色。
- 页面层级只使用 4–16vp 的小范围位移；全屏抽屉等真实边缘表面可从屏幕边缘进入。
- 同一动作只有一个主要动效所有者，避免父容器和子控件重复缩放、滑动或淡入。
- 加载、错误、禁用、选中、运行中和待确认状态必须有静态可辨认表达。
- 支持浅色、深色、大字体、窄屏、横屏、分屏、软键盘和系统安全区。

## 数据与可维护性要求

- 排序、分组和动画参数从 UI 中抽出为纯投影或语义 token，避免散落魔法数字。
- 置顶、归档、membership、工作区顺序和会话时间均以 Host 合同为准。
- 本地排序提示按 hashed account scope 隔离，退出时清理，不进入日志、仓库或通知正文。
- 所有新增行为写入 spec 和 E2E 表；完成状态不得仅由浏览器 mock 推导。
