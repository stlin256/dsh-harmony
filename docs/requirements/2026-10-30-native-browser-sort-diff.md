# 原生预览、文件浏览器、会话排序与 Diff 需求登记

日期：2026-10-30。

本文登记本轮新增要求。逐项实现合同见
[`2026-10-30-native-browser-sort-diff.md`](../specs/2026-10-30-native-browser-sort-diff.md)。
在 spec 冻结以前不新增功能实现；实现完成后仍由独立验收记录决定状态。

## 用户要求

> 图片地址为什么点击了还是复制链接？
> 文件的预览已经突到了状态栏去了
> 加载更多按钮和文件的预览按钮都很打很难看，你修复符合我们风格
> 文件夹地址没法预览，要增加文件浏览器功能
> 为什么工作过程打开还会出现执行了命令xxxx的折叠菜单，这个菜单默认展开吧，不然查看内容还得点两次才能看实际内容
> 以及各个区域很多地方没做好动画，把动画完善了，适配原生鸿蒙特性
> 首页列表要支持拖动排序和置顶
> 新建会话要符合 dsh 的新建会话按钮，现在点击新建会话非常粗糙，非常奇怪，请你修复
> 同时检查当前我们是否能正确呈现 diff，完善此功能
> 优化缓存策略，和预加载策略，提升加载速度
> 上述要求调研并撰写 spec，然后再实施

## 逐项合同

| ID | 优先级 | 必须达到的结果 |
| --- | --- | --- |
| PREVIEW-01 | P0 | 图片消息、Markdown 图片、工作区图片链接点击后直接进入图片预览；不能因为缺少会话 ID 就复制 URL。远程 HTTP(S) 图片、附件图片和工作区相对/绝对图片分别走正确 resolver。 |
| PREVIEW-02 | P0 | 所有原生全屏内容和覆盖层避让状态栏、挖孔及底部系统手势区；内容不得侵入状态栏。返回、关闭和缩放具有系统返回语义。 |
| PREVIEW-03 | P0 | 图片/文本/文件预览和“加载更多”使用 DSH 紧凑图标按钮，不再使用 38–44vp 的宽文字按钮。可触控区域仍尽量满足 44vp，但视觉密度与官方一致。 |
| FILES-01 | P0 | 点击文件或目录地址先通过 Host `workspaceFiles/stat`/`list` 判断类型：目录打开工作区文件浏览器，文件打开对应预览，other/不可读目标显示可恢复错误。禁止靠扩展名猜类型。 |
| FILES-02 | P0 | 文件浏览器显示工作区根、当前路径、返回上一级、文件/目录图标、大小、加载/截断/错误/重试；目录只在会话工作区内浏览，文件内容仍由 Host 授权读取。 |
| FILES-03 | P0 | 文本/代码/Markdown、常见图片使用原生预览；二进制以真实字节读取。大文件按版本化窗口分页，版本变化不得拼接。PDF/Office 允许保存或交给系统能力，不能退化成复制链接。 |
| PROCESS-01 | P0 | “工作过程”打开后，命令/工具详情属于同一披露层，直接显示实际命令和结果；不能要求用户再点一次内层折叠。仅当详情很长或明确存在额外检查页时才提供二级展开。 |
| MOTION-01 | P1 | 页面 pane、菜单/气泡、过程披露、文件/图片预览、列表进入/排序、加载更多、设置二级页均使用 ArkUI 原生动画；统一 100/200/300ms 时序并遵从减少动态效果。流式 token 不播放入场动画。 |
| SESSIONS-01 | P0 | 首页会话支持长按拖动排序；置顶区与普通区不能交叉拖动，blank 会话不可拖，搜索/折叠/隐藏成员不能从完整 membership 中丢失。 |
| SESSIONS-02 | P1 | 拖动结束后先乐观更新，再调用 `workspace/insertSessionBefore`；失败恢复 Host 顺序并显示短状态。置顶/取消置顶调用现有 `workspace/pinSession`/`unpinSession`。 |
| SESSIONS-03 | P1 | “新建会话”恢复 DSH 原版语义：在选定工作区直接创建并进入 composer，复用合适的 blank 会话；不再先打开工作区/目录/preset 整页表单。需要高级预设时使用紧凑弹层。 |
| DIFF-01 | P0 | 工具记录中合法的 unified diff、`oldText/newText` 或 patch 结果使用专用行级渲染：路径头、增、删、上下文和 gap；默认最多 16 行显示头尾，可展开、复制、横向滚动。失败和无旧内容时语义正确。 |
| DIFF-02 | P1 | Diff 识别以真实工具名/参数字段为基础；无法安全推导时保留普通原文，不能凭任意包含 `diff` 的文本猜成成功变更。 |
| CACHE-01 | P1 | 会话列表、工作区、Host 偏好和模型目录采用身份隔离的 stale-while-revalidate；缓存先绘首帧，后台刷新。聊天正文只保存在内存，退出连接时清理。 |
| CACHE-02 | P1 | 同一 endpoint 的并发读取按 client/identity 去重；`pause()` 只取消连接，不清除可复用配置缓存。首屏不等待全部独立请求完成。 |
| CACHE-03 | P1 | 预加载首屏最近会话元数据和当前会话模型目录，不激活未打开会话，不重复发送 `follow/page`。缓存首帧目标 ≤100ms；正常网络冷开第一个可读窗口目标 ≤2s，实测不足时记录阶段耗时。 |
| CACHE-04 | P0 | 加载状态与真实断线分离：加载期间显示骨架/加载态，只有传输确实失败后才显示“连接中断，正在尝试重连”。缓存刷新不闪空、不误报断线。 |

## 共同边界

- 保持 DSH 官方语义、紧凑密度、图标和上下文顺序；手机适配只处理安全区、触控、键盘和窄屏。
- 会话拖排与新建会话以锁定上游 revision 的实现为依据，不发明跨工作区移动或目录猜测。
- 文件 API 保存 Host 返回的 opaque `version`，不解析、不自行比较大小；内容响应必须与请求 offset、实际字节数和 EOF 对齐。
- URL、路径、真实会话标题、凭据和真机截图不进入仓库。测试数据使用合成 ID、合成对话和临时路径。
- 先实现正确性，再完善动画和性能；任何自动化通过都不替代真机安全区、手势和视觉验收。
